# 요구사항 추적표와 수용 기준

모듈 ID(M1~M13)는 [모듈 상세 설계](/plan/03_module_specs.md)를 따른다.
수용 기준의 수치는 초기 목표다. P0에서 실제 데이터를 본 뒤 [결정 기록](/plan/08_decisions.md)에서 확정한다.

## 1. 필수 요구사항

| ID | 요구사항 | 모듈 | 단계 | 검증 방법 | 수용 기준 (초안) |
|---|---|---|---|---|---|
| R1 | 소스코드 분석으로 파라미터·모듈 성능 분석과 개선 | M1, M6, M8 | P1, P3 | ① 파서 커버리지 측정 ② 사람이 만든 정답 파라미터 목록과 비교 ③ SIL에서 개선 전후 비교 | 함수 파싱 성공률 ≥98%. 파라미터 추출 재현율 ≥95%, 정밀도 ≥90%. 개선 제안 중 SIL로 효과가 확인된 비율 리포트 |
| R2 | 시계열 로그로 BMS SW 분석과 개선점 도출 | M2, M3, M8 | P1 | 정답이 정해진 로그 평가셋(이벤트 라벨) | 이벤트 검출 F1 ≥0.9. LLM 진단을 엔지니어가 평가했을 때 타당도 ≥80%. 1 GB 로그 지표 계산 ≤2분 |
| R3 | 신규 기능 개발 능력 | M7, M6, M11 | P4 | 기능별 검증 프로토콜 (실측 또는 합성) | 만충 시간 오차 ≤±10% 또는 ±5분. RUL 예측 구간 적중률(PICP) ≥80%. 스웰링은 센서가 있으면 두께 RMSE를 리포트, 없으면 추정치와 불확도 제공 |
| R4 | 수백 개 파라미터 선별과 최적화 | M5, M11 | P2 | 기존 34개 BO와 같은 데이터로 비교, 학습에 쓰지 않은 프로파일로 교차검증 | 검증 전압 RMSE가 기존과 같거나 낮음. 선별 근거(민감도·식별성) 리포트 자동 생성. 같은 시드로 재현 가능 |
| R5 | 로그 렌더링, 리포트, 편의 기능 | M3 | P1 | 성능 측정, 사용성 테스트 | 1천만 점 로그를 줌·팬했을 때 첫 표시 ≤3초. 리포트 HTML/PDF 생성 ≤30초 |
| R6 | LLM Wiki + OKF (계층화, 캐시, HOTSPOT, 지식 그래프) | M4 | P1 | OKF 검사기, lint, 검색 정답셋 | OKF 적합성 100%. 깨진 링크 0. 검색 상위 5개 적중률 ≥85%. 핫스팟 페이지 자동 갱신 |
| R7 | 도메인 특화 버전 발행 | M6 | P3 | 변종 간 동등성 테스트, 빌드 매트릭스 CI | x86/Android/FW 세 변종 빌드 성공. 기준 대비 SOC 차이 float ≤0.1%p, fixed ≤0.5%p |
| R8 | 기존 코드 분석으로 Wiki와 협업 | M1, M4 | P1 | 모듈 커버리지, drift 감지 테스트 | 소스 모듈의 100%에 위키 페이지가 있음. 코드 변경 후 다음 CI에서 drift 표시 |
| R9 | 사내 배포, 외부 의존 최소화, 라이선스 준수 | M10, M13 | P0~ | 라이선스 게이트, SBOM | 필수 의존성 ≤10개. 금지 라이선스 0. 오프라인 설치 성공 |
| R10 | Python 3.10+ | M10 | P0~ | CI 매트릭스 | 3.10, 3.11, 3.12, 3.13 모두 통과 |
| R11 | Claude 기본, OpenCode 호환 | M8 | P0~ | 양쪽 스모크 테스트 (같은 시나리오 실행) | 핵심 시나리오 10개가 Claude Code와 OpenCode 양쪽에서 성공 |
| R12 | GUI 컨트롤 | M9 | P1~P5 | 사용성 테스트 (비개발자 5명) | 핵심 작업 5개를 설명 없이 완료하는 비율 ≥80% |

## 2. 옵션 요구사항

| ID | 요구사항 | 모듈 | 단계 | 수용 기준 (초안) |
|---|---|---|---|---|
| O1 | 파라미터로 가상 V/I/T 생성 | M11 | P2 | 같은 프로파일에서 실측 대비 전압 RMSE ≤20 mV(ECM) / ≤10 mV(PyBaMM). 센서 노이즈 모델 적용 |
| O2 | ISD, SOH 등 고장·열화 특화 V/I/T | M11 | P4 | 고장 종류 ≥8개. 라벨(시작 시점, 심각도) 포함. 감지 알고리즘 ROC 자동 산출 |
| O3 | AI 추론 성능 최대 활용 | M8, M12 | P1~ | 평가셋에서 가설-검증 루프를 쓰지 않은 기준선보다 진단 정확도가 높음 |

## 3. 비기능 요구사항 (v0.2에서 추가)

| ID | 항목 | 기준 |
|---|---|---|
| N1 | 보안 | 데이터 등급별 처리 규칙 적용. 외부 전송 전 마스킹. 감사 로그 ([M13](/plan/03_module_specs.md)) |
| N2 | 재현성 | 모든 분석 결과에 입력 해시, 도구 버전, 파라미터, 시드 기록 |
| N3 | 오프라인 동작 | LLM 없이 CLI만으로 핵심 분석, 리포트, 최적화 실행 가능 |
| N4 | 플랫폼 | Windows 10/11과 Linux 지원 (경로, DLL/SO 처리) |
| N5 | 성능 | 메모리 8 GB PC에서 10 GB 로그를 청크 단위로 처리 |
| N6 | 언어 | UI와 리포트는 한국어 기본, 영어 전환 가능 |
| N7 | 비용 | 작업별 토큰 예산과 사용량 기록 |
| N8 | 추적성 | 펌웨어 버전 ↔ 파라미터 세트 ↔ 로그 ↔ 분석 결과를 서로 연결 |
