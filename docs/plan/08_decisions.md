# 결정 기록과 미결 질문

| 날짜 | 규칙 |
|---|---|
| 2026-10-15 | 작업 결과는 지정된 개발 브랜치에 **커밋과 push만** 한다. **PR은 만들지 않는다.** |

## 2. 설계 결정 (ADR)

| ID | 결정 | 이유 | 대안 | 상태 |
|---|---|---|---|---|
| ADR-001 | LLM은 해석만, 계산은 결정론적 도구가 맡는다 | 환각·비용 감소, 재현성, LLM 없이도 동작 | LLM이 원시 데이터를 직접 분석 | 확정 |
| ADR-002 | 도구 인터페이스는 MCP 서버 하나(`bms-mcp`)로 통일 | Claude Code·OpenCode 모두 MCP 지원, 중복 구현 방지 | 에이전트별 별도 도구 | 확정 |
| ADR-003 | 에이전트 지침 원본은 AGENTS.md | OpenCode는 AGENTS.md가 우선이고 CLAUDE.md 폴백 제거 보고가 있음. Claude는 import로 해결 | CLAUDE.md 원본 | 확정 |
| ADR-004 | Skills는 `.claude/skills/`에 둔다 | OpenCode 공식 문서가 이 경로를 지원함을 확인 | `.agents/skills/` (Claude Code 인식이 불확실) | 확정 |
| ADR-005 | 지식 형식은 OKF v0.1 + 선택 확장 필드 | 공개 스펙, 마크다운, 벤더 중립, 필수 필드 최소 | 독자 형식, DB 기반 위키 | 확정 |
| ADR-006 | 검색은 SQLite FTS5 기본, 임베딩은 선택 | 표준 라이브러리만으로 동작, 외부 의존 최소 | 벡터 DB | 확정 |
| ADR-007 | GUI는 로컬 웹 UI (빌드 없는 정적 JS + Plotly) | 설치 최소, 리포트와 렌더링 공유, MIT | PySide6(LGPL), NiceGUI | 잠정 (사용성 테스트 후 확정) |
| ADR-008 | LGPL 의존성(asammdf, python-can, PySide6)은 선택 extras로만 | 라이선스 위험 격리 | 필수 포함 | 확정 |
| ADR-009 | A2L은 자체 부분 파서 | pyA2L LGPL, pya2ldb GPL | 외부 파서 | 확정 |
| ADR-010 | 최적화 엔진 기본은 Optuna, 고급은 BoTorch 선택 | torch 의존성 회피, 둘 다 MIT | BoTorch 기본 | 잠정 (기존 BO 환경 확인 후) |
| ADR-011 | C 코어는 C(기존 코드의 C 표준을 따름), 동적 할당 없음, HAL 분리 | BMS가 C로 확인됨(2026-10-15). 모든 변종(FW 포함)에 공통 적용 | C++ | 확정 |
| ADR-012 | 이 `docs/`도 OKF 형식으로 쓴다 | 제품 위키와 같은 도구로 검색·lint 가능 (자기 적용) | 일반 마크다운 | 확정 |
| ADR-013 | LLM 호출은 **사내 gateway API** 경유. Claude Code는 `ANTHROPIC_BASE_URL`(+조직 발급 자격증명), OpenCode는 `opencode.json`의 `provider.<id>.options.baseURL` | 사내 gateway로 코드·로그 전송이 허용됨(2026-10-15). 감사·비용 통제를 gateway에서 일원화 | 직접 외부 API, 사내 모델 전용 | 확정 |
| ADR-014 | 표준 로그 형식 **SBL v1** 제정 (텍스트 TSV/CSV + 엑셀, 채널 이름 규칙, 적합 등급 L0~L3/+R/+S) | 사내 로그가 엑셀·txt로 제각각. 표준이 없어 우리가 정의하면 사내 표준이 될 수 있음 | 기존 형식별 어댑터만 | 확정 ([규격](/spec/sbl_v1.md)) |
| ADR-015 | 파라미터 최적화의 주 시뮬레이터는 **사내 C 모델**(SPM 계열 경량 모델)을 x86으로 빌드해 SIL로 실행 | 최적화 결과를 그대로 BMS에 넣으려면 같은 모델로 맞춰야 함. 경량이라 수백~수천 회 재생 가능 | PyBaMM 기준 최적화 후 이식 | 확정 (PyBaMM은 교차 확인용 선택) |
| ADR-016 | 최적화 대상 파라미터는 **AI가 코드·잔차로 추론**하고 개선량을 예측한다. 기존 34개는 입력이 아니라 블라인드 평가 기준 | 사용자 요구(2026-10-15) | 34개 고정 최적화 | 확정 ([설계](/plan/09_param_inference.md)) |
| ADR-017 | SIL(C 모델 x86 빌드)을 P1 후반으로 앞당긴다 | ADR-015·016의 전제 조건 | P3 유지 | 확정 |
| ADR-018 | **외부 MCP를 쓰지 않는다.** 플러그인 도구는 저장소에 포함된 로컬 MCP 서버(`bms-mcp`, stdio, 네트워크 없음)로만 제공하고, **같은 기능을 CLI로도 제공**한다. Skills는 MCP가 막혀도 CLI(Bash)로 동작하게 쓴다 | 사내에서 외부 MCP 사용 불가(2026-10-15) | 서드파티·원격 MCP | 확정 (로컬 MCP 허용 여부는 Q1 확인) |
| ADR-019 | 현재 우선순위는 **SPM 모델 자체의 정확도 향상**. FW 저전력 모델은 연구 단계이므로 FW·Android 포팅은 뒤로 미루고, 대신 정확도-연산량 파레토 도구로 연구를 지원한다 | 사용자 확인(2026-10-15) | FW 포팅 병행 | 확정 ([트랙](/plan/10_model_accuracy_track.md)) |
| ADR-020 | 최적화 후 잔차를 **파라미터 오차 / 구조 오차 / 잡음**으로 분해하고, 구조 오차는 SPM 확장 후보로 다룬다 | SPM의 구조적 한계를 파라미터가 흡수하는 과적합 방지 | 파라미터 최적화만 | 확정 |
