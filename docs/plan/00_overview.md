# BMS AI Plugin 계획 개요 (v0.3)

> v0.3 (2026-10-15): 사용자 답변 반영 — 사내 gateway로 LLM 사용 확정, BMS는 C, 로그는 엑셀·txt → 표준 로그 형식 [SBL v1](/spec/sbl_v1.md) 제정, 최적화 대상 파라미터는 AI가 추론([설계](/plan/09_param_inference.md)). v0.1→v0.2 변경은 [갭 검토](/plan/06_gap_review.md).

## 1. 목적

BMS SW의 성능 분석과 개선을 돕는 **AI Plugin**을 만든다. Claude Code를 기본으로 하고 OpenCode에서도 쓸 수 있게 한다.
Plugin은 다음 다섯 가지로 구성된다.
- 결정론적 분석 엔진 (Python 3.10+)
- 이식 가능한 C 코어
- 에이전트 지침(Skills)과 MCP 도구
- OKF 기반 지식 위키
- 사람이 쓰기 쉬운 GUI

## 2. 결론

| 구분 | 판단 |
|---|---|
| 전체 가능성 | **조건부 가능.** 필수 12개 항목과 옵션 3개 모두 공개 기술과 허용 라이선스 오픈소스로 구현할 수 있다 |
| 착수 조건 | ① ~~외부 LLM 전송 보안 승인~~ → **사내 gateway API로 해결** (gateway 설정 정보만 필요) ② 실제 BMS C 코드·로그 접근 ③ AI 산출물은 "제안"으로만 쓰고, 사람 리뷰와 SIL 동등성 테스트를 통과해야 양산 코드로 이동 |

## 3. 설계 원칙

1. **계산은 도구, 판단은 LLM.** 수치는 결정론적 Python/C 도구가 계산한다. LLM은 도구가 만든 요약·지표·그래프 조각만 보고 해석한다.
2. **근거 없는 주장 금지.** 리포트의 모든 수치 주장에는 도구 호출 ID, 입력 해시, 도구 버전을 근거로 붙인다.
3. **단일 도구 인터페이스.** Core → MCP 서버(`bms-mcp`) → Claude Code / OpenCode / GUI / CLI 순서로만 의존한다. 같은 기능을 모든 입구가 공유한다.
4. **LLM 없이도 동작.** 모든 분석 도구는 LLM 없이 CLI로 실행할 수 있다. AI는 그 위에 얹는 가치다.
5. **기준값(Golden) 우선.** Python 기준 모델 = C float = C fixed 동등성을 CI에서 상시 확인한다.
6. **최소 의존성과 라이선스 게이트.** 필수 의존성은 허용 라이선스만 쓴다. LGPL은 선택 설치로 분리하고, GPL과 라이선스 없는 코드는 금지한다.
7. **지식은 축적된다.** 분석 결과는 OKF 위키에 쌓고, 다음 분석이 그 위키부터 읽게 한다.
