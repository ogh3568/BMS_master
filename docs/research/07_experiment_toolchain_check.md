# 도구 체인 검증 — C 픽스처 합성 복원 시험

## 목적

사용자의 실제 SPM 코드를 받기 전에 도구 체인이 맞게 동작하는지 확인한다.
대상은 `tests/fixtures/sil_toy/toy_model.c`다. OCV 테이블 + R0 + RC 1개 + 온도 계수로 된 **테스트용 C 픽스처**이고, 배터리 모델 제안이 아니다.

## 방법

1. `cparams`로 C 소스에서 후보 13개를 추출했다. 구조체 필드 5개, static 테이블 원소 6개, 전역 변수 2개(그중 하나는 모델에서 쓰지 않는 값)다.
2. `wrapgen`으로 파라미터 접근 코드를 만들었다. static 테이블까지 이름으로 접근된다. 이어서 `build_shared`로 공유 라이브러리를 만들고 `SilModel`로 실행했다.
3. "참값"에서 4개를 바꾸고 측정 잡음 0.5 mV를 넣어 합성 측정 전압을 만들었다.
   - 바꾼 값: RC 저항 ×1.6, 시정수 ×2, OCV 테이블 1칸 +15 mV, 활성화 에너지 ×1.3
   - 프로파일: 펄스·휴지·정전류 반복, 25 °C와 5 °C 절반씩
4. 원래 값에서 출발해 `infer.pipeline`(선택 → 최적화 → 검증·제외 → 재최적화)을 실행했다.

## 결과 (8회 반복 프로파일, 9,280 샘플)

| 항목 | 값 |
|---|---|
| 시작 RMSE | 76.85 mV |
| 선택 (순서) | RC 저항 → 활성화 에너지 → 시정수 → OCV 테이블[3] |
| 선형 예측 RMSE | 6.31 mV (비선형이 커서 보수적으로 나옴) |
| 최적화 후 RMSE | **0.50 mV** (= 넣어 둔 잡음 수준) |
| 복원값 | RC 저항 0.0240 (참 0.024), 시정수 59.99 (참 60), 활성화 에너지 26,001 (참 26,000), OCV[3] 3.8150 (참 3.815) |
| 영향 없는 후보 | 모델에서 쓰지 않는 전역 변수 → "insensitive"로 자동 제외 |
| 계산 시간 | 약 1초 |

**짧은 프로파일(4회 반복)에서 발견한 점**
- 선형 예측만으로 고르면 용량 파라미터가 5번째로 잘못 선택됐다(위양성).
- 최적화 후 "원래 값으로 되돌려도 RMSE가 거의 안 변함" 검사로 자동 제외됐다(변화 0.006%).
- → 선택 뒤 **검증·제외 단계가 필수**임을 확인하고 `pipeline`에 넣었다.

**식별성 검사**: 온도가 일정한 조건에서 R0와 접촉 저항은 전압에 같은 방식으로 작용한다. 공선성 지수가 100을 넘어 "함께 식별 불가"로 판정됐다. 온도가 바뀌는 로그가 있어야 둘을 구분할 수 있다는 실험 설계 시사점이 나온다.

## 한계와 다음 단계

- 픽스처는 단순하다. 실제 SPM은 파라미터가 많고 비선형이 강하다. 그래서 선형 예측 오차와 반복 횟수가 커질 것이다.
- 실제 코드에 적용할 때 확인할 것
  1. 1회 실행 시간 (민감도 계산은 후보 수 + 1회 실행)
  2. `const`·`#define` 파라미터 비율 (SIL 빌드 방식 결정)
  3. 실측 로그에서의 잔차 구조 (파라미터 오차 대 SPM 구조 오차)
