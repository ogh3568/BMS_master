## M1. 코드 인텔리전스

**목적**: BMS 소스코드를 기계가 질의할 수 있는 구조(심볼, 그래프, 파라미터)로 바꾼다. 결과를 위키와 SIL에 넘긴다.

**입력**: 소스 루트, (선택) `compile_commands.json` 또는 빌드 정의(매크로 값), (선택) A2L·캘리브레이션 파일, 링커 `.map`, git 이력, 이슈 export(CSV).

**처리 단계**
1. **파싱**: tree-sitter + tree-sitter-c (MIT). C++이면 tree-sitter-cpp. 다음을 추출한다.
   - 함수 정의·호출, 전역·정적 변수, 구조체·열거형
   - `#define` 상수, `const` 테이블(1D/2D 룩업), `switch` 기반 상태머신
2. **전처리 보정**: `#if` 분기 때문에 결과가 틀리는 것을 막는다. 빌드 설정의 매크로 값으로 활성 분기만 표시한다. 정밀도가 더 필요하면 libclang(Apache-2.0 + LLVM 예외)을 선택 설치해 쓴다.
3. **파라미터 후보 식별 규칙**
   - 이름 규칙(접두사, `CAL_`, `_THR`, `_TBL`)
   - 섹션 속성(`__attribute__((section(".calib")))`), `const volatile`
   - A2L `CHARACTERISTIC`과 이름 매칭
   - 숫자 리터럴이 직접 쓰인 비교식(매직 넘버)을 "숨은 파라미터"로 보고
4. **고정소수점 추론**: 시프트·스케일 상수 패턴으로 Q-format을 추정한다. 곱셈 뒤 시프트가 없는 경우, 포화 없는 덧셈 같은 위험 패턴을 표시한다.
5. **그래프**: 다음 그래프를 만든다.
   - 호출 그래프, 파라미터 → 함수 → 신호 데이터 흐름(필드 단위 근사), 모듈 의존성
   - 태스크 주기: RTOS 설정과 주기 함수 이름 규칙으로 추출
6. **지표**: 함수별 순환 복잡도, 길이, 팬인·팬아웃, 전역 결합도. 모듈별 ROM/RAM(.map). git churn(90일).
7. **산출물**: `cache/codeintel.sqlite`(심볼·엣지 테이블), `params/registry.yaml` 초안, 위키 페이지(`knowledge/code/**`), 커버리지 리포트(파싱 실패 목록 포함).

**A2L 처리**: pyA2L은 LGPL, pya2ldb는 GPL이다([조사](/research/05_licenses_dependencies.md)). 그래서 `CHARACTERISTIC`, `MEASUREMENT`, `COMPU_METHOD`, `AXIS_PTS`만 읽는 **자체 부분 파서**(약 500줄 목표)를 만든다.

**LLM의 역할**
- 모듈 요약과 설계 의도 추정 (status=draft로 위키에 등록)
- 개선 후보 제안 (지표 + 그래프 조각 + SIL 결과 근거 필수)

**수용 기준**: [추적표](/plan/01_requirements_traceability.md) R1, R8 참조.

**위험**: 벤더 자동생성 코드(AUTOSAR RTE 등)가 대량이면 노이즈가 많아진다 → 경로 제외 규칙(`.bmsignore`)을 둔다.

## M2. 로그 수집·지표 엔진

**어댑터 (플러그인 구조)**

| 형식 | 구현 | 의존성 |
|---|---|---|
| **SBL v1** (`.sbl.tsv/.sbl.csv/.sbl.xlsx`) | `bmskit.logs.sbl` (구현 완료) | 표준 라이브러리 (+openpyxl) |
| **사내 엑셀·txt 시계열** | `bmskit.logs.legacy`: 인코딩(CP949 포함)·구분자·헤더·시간 형식·단위 추정, 한/영 별칭 매핑, 신뢰도와 함께 매핑 초안 → 검토 → 변환 (구현 완료) | 표준 라이브러리 (+openpyxl, `.xls`는 xlrd 선택) |
| CSV/TSV/엑셀 export CSV | 내장 csv + numpy | 필수 |
| Parquet | pyarrow | 선택 `[parquet]` |
| CAN raw + DBC | cantools (MIT, 확인 필요) | 선택 `[can]` |
| MDF4 | asammdf (LGPL-3.0+) | 선택 `[mdf]`, 동적 import만 |
| BLF/ASC | python-can (LGPL) | 선택 `[can]` |
| 사내 바이너리 | 어댑터 템플릿 + LLM이 포맷 문서로 어댑터 초안 생성 | - |

**정규화**: 모든 입력은 SBL v1으로 변환한 뒤 분석한다([규격](/spec/sbl_v1.md)). 채널 매핑(JSON 매핑 파일), 단위 변환, 전류 부호 통일, 시간축 정렬(서로 다른 주기의 신호는 기준 주기로 리샘플링하고 방법을 기록), 품질 검사(결측, 시간 역행, 고착값, 포화, 스파이크).

**대용량 처리**: 청크 단위 스트리밍, 열 단위 읽기, 지표는 누적 계산(streaming statistics) 위주. 목표: 8 GB RAM PC에서 10 GB 로그 처리.

**지표 세트 v1**

| 분류 | 지표 | 기준값이 없을 때 대안 |
|---|---|---|
| SOC | 기준 대비 오차(RMSE, 최대, 구간별) | ① 휴지 구간(전류≈0, ≥30분) OCV로 역산한 SOC ② 고정밀 쿨롱 카운팅 재계산 ③ 만충·완방 앵커 |
| SOH | 용량 추정 추세, BMS SOH와의 차이 | 부분 충전 구간 ΔAh/ΔSOC |
| 셀 균형 | 셀 전압 편차(최대-최소, 표준편차), 휴지 시 편차 추세(mV/일) | - |
| 밸런싱 | 밸런싱 시간, 편차 감소율, 불필요 밸런싱 비율 | - |
| 센서 | 전류 오프셋(휴지 중 평균), 온도 센서 간 이상치 | - |
| 보호 | OV/UV/OC/OT 임계 마진 분포, 플래그 발생 빈도, 오탐 의심 | - |
| 상태머신 | 상태 체류 시간, 천이 행렬, 비정상 천이 | - |
| 열 | 최고·최저 온도, 구배, dT/dt | - |
| 충전 | 실제 만충 시간 vs BMS 예측, CV 진입 SOC | - |
| ISD 징후 | 휴지 중 특정 셀만의 전압 하강률, 평균차 모델 잔차 | - |

**화학 분기**: LFP는 OCV 곡선이 평탄해 OCV 기반 SOC 기준이 약하다. 메타의 `chemistry`로 지표 신뢰도를 조정하고 리포트에 경고를 넣는다.

**이벤트 검출**: 규칙 기반(임계, 변화율)과 통계 기반(robust z-score, 변화점 검출 CUSUM)을 함께 쓴다. 각 이벤트에 `severity`, `evidence`(구간, 신호, 값)를 붙인다.

**로그 → 코드 추적**: 이벤트의 신호/플래그 이름 → 레지스트리의 `writes_signal` 관계 → 함수 → 관련 파라미터 순으로 따라가 "현상 → 코드 위치 → 조정 후보 파라미터"를 자동으로 연결한다.

## M3. 시각화·리포트

- **뷰어**
  - Plotly(MIT) 단일 HTML. plotly.js를 파일 안에 넣어 오프라인으로 열린다.
  - LTTB 다운샘플링(약 50줄 자체 구현). 줌하면 원본 해상도를 다시 요청한다(GUI 모드).
- **표준 화면 세트**: 팩 V/I/SOC, 셀 전압 히트맵(시간×셀), 온도 히트맵, 상태 타임라인, 이벤트 마커, 기준 대비 오차. 모든 축은 동기 줌.
- **리포트 템플릿 (Jinja2, BSD)**: ① 로그 진단 ② 코드 분석·핫스팟 ③ 파라미터 최적화 ④ FW 버전 비교 ⑤ 신규 기능 검증 ⑥ 합성 데이터 검증.
- **리포트 구조 (공통)**
  1. 요약 (3줄, AI 작성이면 표시)
  2. 주요 발견 (심각도, 근거 run_id, 관련 코드·파라미터)
  3. 그래프
  4. 권고 조치와 예상 효과
  5. 재현 정보 (입력 해시, 도구 버전, 명령)
- **출력**: HTML(기본), PDF(브라우저 인쇄 CSS), Markdown(위키 등록용).

## M4. 지식 위키 엔진

**번들 구조**: [아키텍처 §7](/plan/02_architecture.md)의 frontmatter 확장을 쓴다.

```
knowledge/
├── index.md   _hot.md   log.md
├── code/{modules,functions,params}/       # M1이 자동 생성 (author: ai)
├── algorithms/{soc,soh,balancing,isd,swelling,rul,ttf,thermal}/
├── cells/                                   # 셀별 사양·파라미터 세트
├── experiments/                             # 최적화·분석 실행 요약
├── findings/                                # 로그·코드 분석 발견사항
├── knowhow/                                 # 사람 노하우, 트러블슈팅, ADR
└── raw/                                     # 원천 요약 (불변)
```

**계층(점진적 공개)**

| 계층 | 내용 | 크기 상한 | 로딩 |
|---|---|---|---|
| L0 | `_hot.md` 핫스팟 상위 20개 개념의 2줄 요약 | ~2k 토큰 | 세션 시작 때 항상 |
| L1 | 각 디렉터리 `index.md` (개념별 1줄) | ~1k 토큰/개 | 탐색할 때 |
| L2 | 개념 페이지 | ~3k 토큰 권장 | 필요할 때 |
| L3 | `raw/`, 코드 원문 | 제한 없음 | 근거 확인할 때만 |

**캐시**
1. 페이지 내용 해시 → 요약 캐시(`cache/kb_summaries.json`). 바뀐 페이지만 다시 요약한다.
2. SQLite FTS5 전문 검색 + 태그·타입 필터. 한국어는 n-gram(trigram) 토크나이저를 쓴다.
3. L0/L1처럼 잘 바뀌지 않는 텍스트를 프롬프트 앞쪽에 고정해 LLM 프롬프트 캐시 적중률을 높인다.
4. (선택) 임베딩 검색. 사내 임베딩 모델이 있을 때만 쓴다. 기본은 FTS로 충분하다고 본다.

**HOTSPOT 점수**

`score = 0.25·norm(조회 30일) + 0.25·norm(코드 churn 90일) + 0.2·norm(연결 이슈/발견 수) + 0.15·norm(그래프 중심성) + 0.15·norm(최근 로그 이상 연관)`

- 가중치는 설정 파일로 바꿀 수 있다.
- 매일(또는 CI에서) `_hot.md`와 각 페이지의 `hot` 필드를 갱신한다.

**지식 그래프**
- frontmatter `relations`와 본문 링크로 `cache/graph.json`(노드·엣지)을 만든다.
- 중심성(PageRank), 고아 노드, 순환을 계산한다. 표준 라이브러리로 구현한다.
- 시각화는 GUI의 그래프 뷰에서 한다. OKF 레퍼런스 정적 뷰어와 호환되게 한다.

**운영 연산 (Karpathy 패턴)**
- `ingest`: 원천 → raw 요약 → 관련 개념 페이지 갱신
- `query`: L0 → L1 → L2 탐색 후 답변. 좋은 답변은 페이지로 승격
- `lint`: 깨진 링크, 고아 페이지, `status: draft` 30일 초과, 근거 없는 수치, 코드 drift

**거버넌스**
- AI가 만든 페이지는 `author: ai`, `status: draft`로 시작한다. 소유자가 리뷰한 뒤 `reviewed`가 된다.
- `kb.upsert`는 diff를 보여주고 승인을 받아야 반영된다.

**drift 감지**: `resource`의 git 해시와 현재 해시가 다르고 그 파일이 바뀌었으면 `needs_review` 태그를 붙인다. CI/훅에서 실행한다.

## M5. 파라미터 선별·최적화

> **v0.3 변경**: 최적화 대상은 AI가 코드와 잔차로 추론하고 개선량을 예측한다. 주 시뮬레이터는 사내 C 모델(SPM 계열)의 SIL 빌드다. 상세는 [파라미터 추론 설계](/plan/09_param_inference.md). 아래 모델 계층 표의 PyBaMM 항목은 교차 확인용 선택 사항이 된다.

**모델 계층**

| 충실도 | 모델 | 1회 시뮬 시간(가정) | 용도 |
|---|---|---|---|
| 낮음 | ECM 1RC/2RC (자체 구현, numpy) | ms 단위 | 스크리닝, 코드 캘리브레이션 |
| 중간 | SPM/SPMe (PyBaMM) | 0.1~1 s | Sobol, BO 초반 |
| 높음 | DFN (PyBaMM) | 1~30 s | 최종 BO, 검증 |

**파이프라인**
1. **후보 정의**: 레지스트리에서 `kind ∈ {physical, model, calibration}`, 범위, 스케일(log/linear)을 읽는다.
2. **스크리닝 — Morris**: r=20~50 궤적, 저충실도 모델. μ*, σ로 상위 30~60개를 고른다. 목적함수 여러 개(전압 RMSE, 휴지 회복, 고율 구간)를 따로 본다.
3. **정량 민감도 — Sobol**: Saltelli 샘플링(N=512~2048), 1차·총효과 지수. SALib(MIT)를 쓰거나 자체 구현.
4. **식별성 분석**
   - 최적점 근처 야코비안으로 Fisher 정보행렬과 상관행렬을 계산한다.
   - |ρ|>0.95인 묶음은 하나만 남기거나 비율로 다시 파라미터화한다(예: 확산계수·입자 반경 → 확산 시간상수).
   - 필요하면 프로파일 우도로 확인한다.
5. **최적화**
   - 엔진은 Optuna(MIT, 기본 경량)와 BoTorch(MIT, 선택 `[bo]`: SAASBO·TuRBO·다중 충실도 KG)를 둔다.
   - 기존 34개 + diffusivity 결과를 초기점으로 쓴다(warm start).
   - 저충실도 → 고충실도로 단계를 올린다. 병렬 실행은 process pool, 사내 서버가 있으면 작업 큐.
6. **목적함수**: 여러 프로파일(OCV, HPPC, 주행, 급속충전)과 여러 온도의 가중 RMSE. 휴지 회복 구간 가중치를 따로 둔다. 범위 벌점.
7. **불확도**
   - 최종 후보 주변을 PyBOP(BSD-3)의 MCMC 샘플러로 샘플링해 사후분포를 구한다. 비용이 크면 라플라스 근사를 쓴다.
8. **검증**: 학습에 쓰지 않은 프로파일, 온도, 노화 단계로 교차검증한다. 과적합 지표는 학습/검증 RMSE 비율이다.
9. **결과 반영**: `params/sets/<cell>/<version>.yaml`과 위키 `experiments/` 페이지. 사람이 확정하면 레지스트리 `optimize` 플래그를 갱신한다.

**LLM의 역할**: 탐색 범위가 물리적으로 타당한지 검토, 상관 묶음의 재파라미터화 제안, 결과 해석. 수치 계산은 하지 않는다.

**리소스 추정**: DFN 1회 10 s, 2,000회 BO 기준 직렬 약 5.6시간. 16코어 병렬이면 약 30분대(가정). 저충실도 단계로 고충실도 호출을 70% 이상 줄이는 것이 목표다.

## M6. C 코어·SIL·특화 버전

**C 코어 추출 전략**
1. 기존 BMS 코드에서 알고리즘 부분(SOC/SOH/밸런싱 판단/보호 판단)을 HAL 의존 없이 컴파일할 수 있게 분리한다. 기존 코드를 고치지 않고 스텁(stub) HAL로 감싸는 방식을 우선한다.
2. 분리가 어려우면 기존 코드를 "그대로" x86으로 빌드한다. 레지스터·드라이버 접근은 스텁으로 바꾼다.

**SIL 재생 하네스**
- 표준 로그 → 입력 신호 주입 → 알고리즘 주기 호출(로그 시간축으로 스텝) → 출력 기록 → 기준 대비 오차, 실행 시간(사이클 근사) 측정.
- 파라미터 세트를 바꿔 끼울 수 있다. 캘리브레이션 구조체는 메모리를 직접 덮어쓰거나 파일로 로드한다.

> **v0.4 우선순위 (ADR-019)**: FW 저전력 모델은 연구 단계다. 지금은 **x86 공유 라이브러리 + Python 바인딩(SIL용)**만 만든다. Android·FW 저전력·고정소수점 변종은 연구 결론 후 착수한다. 그 전까지는 [정확도-연산량 파레토](/plan/10_model_accuracy_track.md)로 연구를 지원한다.

**특화 버전 매트릭스 (목표 상태)**

| 변종 | 산출물 | 특징 | 검증 |
|---|---|---|---|
| x86/x64 공유 라이브러리 | `.so`/`.dll` + C 헤더 + Python ctypes 바인딩 | float, 디버그 트레이스 | 기준 모델과 동등성 |
| Android | NDK `.so` + JNI 래퍼 + AAR | float, 스레드 안전, 상태 직렬화 | 에뮬레이터 스모크 |
| FW 저전력 | 정적 라이브러리 | fixed-point, malloc 없음, 실행 주기 감소·이벤트 기반 갱신, 슬립 중 적분 보정 | fixed vs float 오차 예산 |
| (선택) WASM | `.wasm` | GUI 안 시뮬 | - |

**오차 예산(초안)**: SOC 최대 차이 float 0.1%p, fixed 0.5%p. 전압 예측 차이 1 mV. 오차 예산을 넘으면 CI 실패.

**저전력 프로파일 설계 포인트**
- 휴지 중 SOC 갱신 주기를 늘리고 자가방전 보정을 적분식으로 한다.
- 테이블 보간은 구간 탐색 캐시를 둔다.
- 32비트 곱셈 누산 범위를 정적으로 확인한다.

## M7. 신규 기능 개발

> **v0.4**: 현재 최우선 "기능"은 SPM 모델 정확도 향상이다. 구조 확장(전해질 보정, 열 결합, 히스테리시스 등)은 [모델 정확도 트랙](/plan/10_model_accuracy_track.md)에서 같은 절차로 다룬다.

**공통 개발 절차 (Skill: `feature-dev`)**
1. 요구 스펙 템플릿 작성: 입력 신호, 출력, 주기, 정확도, MCU 예산
2. 위키·문헌 조사 → 후보 알고리즘 2~3개 비교표
3. 사용자 C 코드에 기능 초안을 패치로 작성 (새 모델·별도 구현을 만들지 않음, ADR-021)
4. 검증: 실측 로그 + M11 합성 데이터. 지표와 수용 기준은 스펙에 있다
5. MCU 예산 확인(.map, 사이클 추정) — FW 단계에서
6. SIL 동등성 테스트, 위키 등록, 리포트

**기능별 설계**

| 기능 | 알고리즘 후보 | 입력 | 출력 | 검증 데이터 |
|---|---|---|---|---|
| 만충 예상 시간 (TTF) | ① 충전 프로파일(CC/다단 CC/CV) + ECM 전진 시뮬 ② 오프라인 2D/3D 테이블(SOC×T×SOH) ③ 실측 충전 이력으로 보정 | SOC, T, SOH, 충전기 한계, 목표 SOC | 남은 시간과 신뢰 구간 | 충전 로그 (실측 만충 시각) |
| 예상 유효 수명 (RUL) | ① 경험 모델 Q = 1 − a·√t − b·Ah^z (캘린더 + 사이클) + 파티클 필터 ② GP 회귀 ③ 스트레스 요인(SOC 체류, 온도, C-rate) 히스토그램 기반 | SOH 이력, 사용 히스토그램 | EOL(예: 80%)까지 남은 시간·사이클과 예측 구간 | 장기 열화 데이터 (사내 또는 공개, [조사](/research/06_datasets_regulations.md)) |
| 스웰링 | ① 가역: 두께 = f(SOC)(흑연 삽입 팽창) + α·ΔT ② 비가역: SEI·가스 성장 ∝ 용량 손실, 캘린더 시간, 고온 고SOC 체류 ③ 센서가 있으면 칼만 필터로 융합 | V, I, T, SOH, (두께/압력) | 추정 두께 증가율, 경고 단계 | 두께·압력 측정 실험 (필수 요청) |
| ISD/ISC | ① 평균차 모델 + RLS 잔차 ② 휴지 중 셀별 자가방전율 비교 ③ pseudo-OCV 1차 차분 | 셀 전압, 전류, T | 의심 셀, 등가 단락 저항 추정, 신뢰도 | 외부 저항 모사 실험 + 합성 데이터 |
| SOP/SOF (추천) | ECM 기반 펄스 전력 예측 | V, I, T, SOC | 2/10/30 s 가용 전력 | HPPC |

## M11. 합성 데이터·고장 주입

**생성 파이프라인**: 셀 파라미터 세트 → 팩 구성(직병렬, 셀 간 편차 분포: 용량 σ, 저항 σ, 초기 SOC σ) → 부하 프로파일 → 열 모델(집중 열용량) → 셀/팩 시뮬 → 센서 모델 → 표준 로그 + 라벨.

**프로파일 라이브러리**: CC/CV 충전, 다단 급속충전, HPPC, GITT, 표준 주행 사이클(사용자가 CSV로 제공), 캘린더 휴지, ESS 일일 패턴, 모바일 기기 사용 패턴.

**센서 모델**: 오프셋, 게인 오차, 양자화(ADC 비트), 지연, 백색 노이즈, 1/f 드리프트, 샘플 누락, 통신 지연.

**고장·열화 라이브러리 (라벨 포함)**

| 고장 | 모델 | 파라미터 |
|---|---|---|
| 내부 단락(ISC/ISD) | 셀에 병렬 저항 R_isc(t) | 시작 시각, R 값(1 Ω~1 kΩ), 진행 형태(계단/점진) |
| 용량 감소 | Q_max 스케일 | SOH 목표, 노화 경로 |
| 저항 증가 | R0·RC 스케일 | 배율 |
| 리튬 플레이팅 징후 | 저온 고율 충전 시 전압 plateau·휴지 이완 이상 | 조건 |
| 셀 불균형 | 초기 SOC·자가방전율 편차 | σ |
| 접촉 저항 증가 | 버스바 직렬 저항 | 값·진행 |
| 센서 고장 | 고착, 드리프트, 단선(개방), 노이즈 증가 | 종류·시점 |
| 열 이상 | 국부 발열원, 냉각 고장 | 열량·위치 |
| 스웰링 | 두께 신호(가역 + 비가역) | 속도 |

**라벨 형식**: `labels.json` = [{fault, cell, t_start, t_end, severity, params}]. M12 평가에 바로 쓴다.

| S1 내부 | 일반 노하우, 공개 논문 요약 | 허용 |

- **마스킹**: 파라미터 실제 값 → 정규화 값 또는 범위, 프로젝트·고객명 → 가명, 코드 주석 속 개인정보 제거.
- **통제 지점**: MCP 서버가 응답을 내보내기 전에 마스킹 정책을 적용한다. 등급은 파일 경로 규칙과 메타로 정한다.
- **감사 로그**: 어떤 도구가 어떤 데이터를 LLM 컨텍스트로 넘겼는지 기록한다(`runs/audit.jsonl`).
- **설정 프로파일**: `gateway`(기본: 사내 gateway 경유, 감사 로그) / `secure`(마스킹 강제) / `offline`(LLM 없이 도구만).
- **gateway 연동**: 모든 LLM 호출은 사내 gateway를 거친다(ADR-013). 토큰 사용량·감사는 gateway 로그와 `runs/audit.jsonl`을 함께 쓴다.
