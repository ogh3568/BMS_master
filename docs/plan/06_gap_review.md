# v0.1 계획 갭 검토

## 1. 검토 방법

- 요구사항 15개(필수 12 + 옵션 3)를 하나씩 "입력이 무엇인가 / 정답을 어떻게 아는가 / 누가 언제 쓰는가 / 실패하면 어떻게 아는가" 네 질문으로 점검했다.
- 추가 조사로 v0.1의 가정을 다시 확인했다([조사](/research/index.md)).

## 2. 발견한 갭과 보완 내용

| # | 갭 (v0.1) | 왜 문제인가 | v0.2 보완 | 위치 |

## 3. 아직 남은 갭 (데이터를 받아야 풀림)

| # | 남은 갭 | 필요한 것 |
|---|---|---|
| O-1 | 실제 코드 규모·구조를 몰라 M1·M6 공수 추정 오차가 큼 | 코드 접근 (Q2) |
| O-2 | 기존 BO의 모델·목적함수를 몰라 M5 재현 방법이 미정 | 기존 BO 코드와 설정 (Q4) |
| O-3 | 로그 포맷과 기준값 유무를 몰라 M2 어댑터 우선순위가 미정 | 샘플 로그 (Q3) |
| O-4 | 보안 정책에 따라 아키텍처 기본 프로파일이 달라짐 | 보안팀 답변 (Q1) |
| O-5 | 기능안전 등급(ASIL 등)과 개발 프로세스(ASPICE 등)에 따라 산출물 형식 요구가 생길 수 있음 | 품질 부서 확인 (Q9) |
| O-6 | 수용 기준 수치는 초안 | P0 데이터 확인 후 확정 |

## 4. 검토 결론

- v0.1의 방향(도구 중심, MCP 공용, OKF 위키, SIL)은 그대로 유지한다.
- 빠져 있던 것은 주로 **"측정과 계약"**이다: 데이터 계약, 평가, 기준값, 보안, 추적성.
- v0.2에서 이 부분을 설계에 넣었다. 남은 갭은 실제 데이터를 받으면 해소된다.
